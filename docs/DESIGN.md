# Mimizuku UI/UX デザイン

この文書はMimizukuのUI/UXに関する正典である。画面固有の構成は[`design/main-window.md`](./design/main-window.md)、再利用する表示と操作は[`design/interaction-patterns.md`](./design/interaction-patterns.md)で定義する。実装技術を決めるADRやスライスの受け入れ条件と矛盾する場合は、要求の意味をこの文書、技術選択をADR、導入時期を実装計画の責務として整合させる。

## 対象利用者と利用場面

Mimizukuは、会議、インタビュー、講義などをMacで記録し、後から音声と文字起こしを照合しながらノートへ仕上げる人のためのプロ向け音声ツールである。利用者は録音中に別の作業へ集中し、記録後には長いセッションから事実を素早く見つけ、聞き直し、修正し、メモやTODOとして整理する。

主作業は記録後の確認と編集である。通常の画面密度は情報量と可読性を両立する中密度とし、音声経路、復旧理由、モデル状態などの技術情報は問題の理解や解決に必要なときだけ段階的に開示する。録音中も記録後も別製品のような画面へ分断せず、同じセッションの情報構造で扱う。

目指す印象は「静かなmacOSネイティブUI」である。専門的な能力を派手な装飾で主張せず、状態の正確さ、操作の予測可能性、長時間読める落ち着きによって信頼を得る。

## 体験原則

### 静かな捕捉

録音中は必要な状態と停止操作を常に確認できる一方、不要なアニメーション、通知、モーダル表示で会議を妨げない。正常な進行は近接した受動的フィードバックで示し、利用者の介入が必要な問題だけを目立たせる。

### 記録状態を誤認させない

待機、録音中、停止処理中、完了、中断、復旧必要、失敗を同じ見た目にしない。録音中を色だけで示さず、文言、形状、SF Symbol、経過時間を組み合わせる。「完了」は音声と保存対象の文字起こしが確定した後だけ表示し、停止要求を受けただけの状態に使わない。

### 時間軸上の事実を正確に示す

マイクとシステム音声、再生位置、文字起こしはセッション開始を原点とする共通時間軸で対応させる。2音源を視覚的に混ぜず、同時刻として比較できるよう同期して示す。時刻不明、不完全な末尾、未確定結果を確定済みの事実として装わない。

### 技術詳細は必要時に開示する

通常表示では「録音が中断されました」「復旧が必要です」のように利用者の次の行動を先に伝える。音声トラック、保存パス、内部状態、診断値などはinspector、詳細開示、診断画面へ置き、一次操作と同じ階層に並べない。

### ローカル処理への信頼

音声と文字起こしがMacの外へ出ないことを、初回案内、権限要求、処理中の文言、設定で一貫して伝える。ネットワーク送信を連想させる曖昧な「アップロード」「クラウド処理」という文言や演出を使わない。保存場所や復旧操作を説明するときも、ローカルデータを対象としていることを明示する。

## 情報階層

情報の優先順位は次のとおりとする。

1. 録音中か、保存が完了したか、介入が必要かという記録の安全性。
2. 選択中セッションの再生位置、文字起こし、話者ラベルという時間軸上の内容。
3. セッションの選択、検索、タグ、ステータスという整理情報。
4. 要約、TODO、メモという派生・付加情報。
5. 音声形式、トラック詳細、復旧理由、診断値という技術情報。

主要操作は現在注目している対象の近くに置く。アプリ全体に作用する操作はメニューバーまたは標準メニュー、選択中セッションに作用する操作はツールバーまたは対象ペイン、テキスト選択に作用する操作はコンテキストメニューに置く。同じ操作を複数箇所に置く場合も名称と結果を一致させる。

## 視覚言語

### 色

システムアクセント色とセマンティック色を使い、ライト、ダーク、Increase Contrast、Reduce Transparencyなどの環境に追従する。独自の固定カラーパレットは導入しない。録音、警告、エラー、選択、未確定を色だけで区別せず、文言、シンボル、境界、形状の少なくとも一つを併用する。

赤は録音中や破壊的結果など、macOSの意味と一致する限定的な箇所に使う。大きな面をブランド色で塗らず、本文と波形の可読性を優先する。波形の2レーンは色が失われてもラベルと位置で識別できるようにする。

### タイポグラフィ

SF Proと日本語のシステムフォント連携、およびSwiftUIのセマンティックなテキストスタイルを使う。独自フォントや固定ポイント指定は、ブランド資産または可読性上の根拠が確定するまで導入しない。文字起こし本文は長時間読める行長と行間を確保し、3行以上の本文を詰めた行間にしない。

macOSはDynamic Typeをサポートせず、SwiftUIの`dynamicTypeSize`も利用者が変更できないため、「Dynamic Type対応」を要件にしない。代わりにセマンティックなシステム書体、文字を切らない可変レイアウト、macOSのアクセシビリティ設定を尊重し、文字起こしなど読み取りが主目的の領域には将来の表示倍率または文字サイズ調整を妨げない構造を用いる。

### シンボル、素材、形状

ツールバー、メニュー、ステータスにはSF Symbolsを優先し、隣接するラベルと意味・ウェイトを合わせる。シンボルだけでは意味が曖昧な状態や主要操作にはテキストラベルまたはアクセシビリティラベルを付ける。ロゴや商標としてSF Symbolsを使わない。

階層は標準Material、ペイン、separator、選択状態で表現する。独自のぼかし、重いドロップシャドウ、カードの多重入れ子で階層を作らない。角丸、余白、コントロールサイズは標準コンポーネントの値を基準とし、Web由来のpx/remトークンへ置き換えない。

### 密度と余白

セッション一覧とメタデータは走査しやすい中密度、文字起こしは読解しやすい密度、診断情報は必要時に比較しやすい高密度を許容する。余白を装飾として増やすのではなく、時間軸、話者、セクション、操作群の境界を伝えるために使う。ウィンドウ縮小時は内容を一律に圧縮せず、優先度の低いペインを畳む。

## フィードバックとエラー

操作への反応は即時に表示する。所要時間が分かる処理には正確なdeterminate progress、分からない処理にはindeterminate progressと具体的な処理名を示す。停止可能な処理には安全な範囲でキャンセルを提供し、停止によって結果を失う場合は影響を説明する。

正常状態や自動復旧は対象の近くへ受動的に表示する。アラートは、回復不能なデータ損失、権限によって操作を続行できない場合、利用者の判断が直ちに必要な場合に限定する。エラーは「何が起きたか」「保存済みのものは何か」「次にできる操作」を示し、内部エラーコードだけを本文にしない。

## アクセシビリティ

- VoiceOverではペイン、セッション、話者、時刻、録音状態、再生状態、進捗、警告、操作の名前と値を読み上げられるようにする。波形そのものに依存せず、現在位置と時間をテキストでも提供する。
- キーボードだけで主要操作、ペイン移動、一覧選択、再生、文字起こし閲覧、inspector開閉へ到達できるようにする。フォーカスリングを隠さない。
- Reduce Motion有効時は移動量の大きい遷移や連続的な装飾アニメーションを省き、状態変化は短いクロスフェードまたは即時更新で伝える。録音経過時間や再生カーソルなど、情報そのものの更新は停止しない。
- Increase Contrastおよびライト／ダーク表示で、テキスト、選択、separator、波形、警告が識別できることを確認する。独自色を使う場合もシステム設定に追従する。
- 未確定、エラー、録音中、話者を色だけで示さない。テキスト、シンボル、形状、位置を併用する。

## キーボードと標準操作

標準メニューとショートカットを操作の正典とし、ツールバーやコンテキストメニューは同じCommandへ接続する。既存の録音開始／停止は⌘R、議事ログは⌘Lを維持する。選択したセッションの再生／停止は、テキスト入力中やメニュー操作中でない場合にSpaceで切り替える。削除、編集、コピー、検索、ウィンドウ／inspector表示はmacOSの標準名称とショートカットを優先する。

詳細なフォーカス順序と競合回避は[`design/interaction-patterns.md`](./design/interaction-patterns.md)で定義する。

## プライバシー

音声、文字起こし、要約、TODO、メモはオンデバイスデータとして扱う。権限要求は操作の直前に目的を説明し、マイクとシステム音声録音を別々に理解できるようにする。診断、復旧、エクスポートは対象データと保存先を利用者が確認できるようにし、暗黙の外部送信を行わない。

画面共有やスクリーンショットに機密情報が含まれうるため、セッション内容を不要な通知やメニューバーのポップオーバーへ展開しない。ロックや自動秘匿などの追加機能は別スライスで仕様化し、この文書だけを根拠に先行実装しない。

## ブランド拡張点

アプリアイコン、ロゴ、固有のアクセント、イラストレーションなどのブランド資産が確定した場合は、この文書に用途、代替表示、ライト／ダーク対応、アクセシビリティ上の意味を追記する。ブランド資産が決まるまではシステム色、システム書体、SF Symbols、標準Materialを既定とし、仮の固定パレットやフォントを正典化しない。

## 出典と適用方針

- [Apple Human Interface Guidelines: Designing for macOS](https://developer.apple.com/design/human-interface-guidelines/designing-for-macos/)を第一の基準とし、ウィンドウの可変性、キーボード操作、標準コンポーネント、利用者による表示調整をMimizukuへ適用する。
- [Apple HIG: Accessibility](https://developer.apple.com/design/human-interface-guidelines/accessibility/)、[Color](https://developer.apple.com/design/human-interface-guidelines/color/)、[Typography](https://developer.apple.com/design/human-interface-guidelines/typography/)、[SF Symbols](https://developer.apple.com/design/human-interface-guidelines/sf-symbols/)、[Feedback](https://developer.apple.com/design/human-interface-guidelines/feedback/)、[Progress indicators](https://developer.apple.com/design/human-interface-guidelines/progress-indicators/)を、視覚表現と状態通知の基準にする。
- [Voice Memos User Guide](https://support.apple.com/guide/voice-memos/welcome/mac)は録音一覧、波形シーク、Spaceによる再生／停止という操作構造を参考にする。[Notes User Guide](https://support.apple.com/guide/notes/view-your-notes-apd8b73d28be/mac)は一覧と選択内容を分離する構造を参考にする。見た目を複製せず、Mimizuku固有の2音源、統合文字起こし、ノートを同じ時間軸へ再設計する。
- Googleの[DESIGN.md](https://github.com/google-labs-code/design.md)から、人間とAgentが共有する自己完結したデザイン正典という考え方だけを採用する。同仕様はalphaでWeb向けのsRGB固定色、固定フォント、px/em/remトークンを中心とするため、そのYAML schemaとtoken値には準拠しない。

調査メモを別のスクラップ文書として残さず、採用した原則と却下理由はこの節へ統合する。
