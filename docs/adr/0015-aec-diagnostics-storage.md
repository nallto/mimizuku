# ADR-0015: AEC診断データは$XDG_STATE_HOMEへ分離し、揮発性起動引数で有効化する

- ステータス: Accepted
- 日付: 2026-07-30
- 関連: #75 / ADR-0006(保存分類を拡張)/ ADR-0007(セッションデータとの分離)/ ADR-0014

## Context(背景)

#75の調査には、同一試行のAPM入出力(raw capture / render参照 / 処理後capture)と正規化前後の実測時刻を音声ファイル+構造化ログとしてローカル保存する診断経路が必要になった。この診断データには次の性質がある。

- **AEC処理前のマイク原音を含む。** ADR-0014が正式音源から排除した「システム音声が回り込んだ原音」を、調査のためにあえて保存する。正式なセッションデータと同じ場所に置くと、後段(ミックス・エクスポート・検索)が誤って拾い得る。
- **一時的だが、自動再構築できない調査データである。** 利用者データではなく、試行をやり直せば再取得できるものの、同一試行の結果は復元できず、アプリやOSが任意に削除すべきcacheではない。ADR-0007のmeta.json / transcript.jsonlに混ぜない制約が承認済み(#75計画)。
- **常時記録してはならない。** raw録音が意図せず全セッションで継続する事故を構造的に防ぐ必要がある。

ADR-0006はユーザーデータ(`$XDG_DATA_HOME`)・設定(`$XDG_CONFIG_HOME`)・キャッシュ(`$XDG_CACHE_HOME`)を定義したが、「アプリが生成する一時的なログ・計測データ」の分類を持たない。

検討した代替案:

- **セッションディレクトリ内(`$XDG_DATA_HOME/mimizuku/sessions/`)に置く**: 試行と録音の対応は取りやすいが、恒久ユーザーデータと調査用raw音声が混ざり、ADR-0007の形式にも診断情報が漏れ込みやすい。承認済み制約に反するため却下。
- **`$XDG_CACHE_HOME`に置く**: cacheは「消えてもアプリが自動再構築できるデータ」の分類であり、消えたら再計測が必要な診断結果は意味が合わない。OSやユーザーのキャッシュ掃除で計測中のデータが消え得るため却下。
- **永続フラグ(`defaults write`)で有効化**: 切り忘れるとraw録音が全セッションで継続する。設定の置き場所も`$XDG_CONFIG_HOME`とするADR-0006の方針と衝突する(UserDefaultsはmacOSの`~/Library/Preferences`)。却下。
- **診断UIトグルで有効化**: 発見しやすいが、開発者専用機能をUIへ露出させることになり、切り忘れリスクも永続フラグと同じ。#75の時点では不要と判断し却下(恒久化するなら再検討)。

## Decision(決定)

1. **保存分類として`$XDG_STATE_HOME`(既定`~/.local/state`)を新設する。** XDG Base Directory仕様のstateは「ログ・履歴など、移植する価値はないがセッションを跨いで残るデータ」の分類であり、診断データの性質に一致する。解決規則はADR-0006と同じ(絶対パスのみ有効、相対・未設定は既定へフォールバック)。
2. AEC診断データは`$XDG_STATE_HOME/mimizuku/aec-diagnostics/<yyyyMMdd-HHmmss>/`へ試行単位で保存する。同一秒のディレクトリ名が既に存在する場合(開始失敗後の再試行等)は、`SessionLayout`と同様に`-2`以降を付けて衝突を避ける。**既存ディレクトリへの上書きは禁止。** 内容は音声4ファイル(capture-raw / capture-processed / render-received / render-fed)、frames.jsonl、speech.jsonl、meta.json。**ADR-0007のセッションデータ(meta.json / transcript.jsonl)へは一切書かない。**
3. **診断データはデバイス外へ出さない**(ハード制約2)。リポジトリへのコミットも禁止(録音・文字起こしのコミット禁止と同じ扱い)。
4. **有効化は揮発性の起動引数のみ**: `open -n <app> --args -AecDiagnosticsEnabled YES`(UserDefaultsのargument domain)。プロセス限りで消え、何も永続化されない。これは設定ではなく一回限りの開発診断トリガであるため、ADR-0006の設定方針(`$XDG_CONFIG_HOME`)の対象外とする。無効時は診断ディレクトリもwriterタスクも生成しない。
5. **保持・削除は手動**とする。アプリは診断データを自動削除も自動ローテーションもしない(計測中のデータを消さない)。不要になったら`aec-diagnostics/`ディレクトリごと削除する。手順はdocs/development.mdに記載する。
6. **開発者専用診断として保持する限り、本ADRが有効である。** #75クローズ時に診断経路(記録コード)を削除するか残すかを判断するが、残す場合も開発者専用診断である限り本ADRの範囲内とする。利用者向け機能(トラブルシュート等)へ昇格させる場合は、UI露出・保持方針を含めて新しいADRで決め直す。

## Consequences(結果)

- 得るもの:
  - raw原音を含む調査データが正式なユーザーデータ空間から物理的に分離され、後段機能・エクスポートが誤って拾わない。
  - 有効化が揮発するため、raw録音が意図せず継続する事故が構造的に起きない。
  - 診断データをディレクトリ単位で一括破棄できる(安全な削除手順はdocs/development.mdに置く)。
- 失うもの・代償:
  - raw音声と文字起こしは、手動削除するまで端末上に残り続ける。
  - 自動ローテーションがないため、容量は削除するまで無制限に増える。48kHz/mono/Int16の音声4本で概算約1.4GB/時を消費する。
  - 試行のたびに引数付き起動が必要(利便性より事故防止を優先)。
  - stateという4つ目の保存分類が増え、開発者が把握すべき場所が1つ増える。
  - 診断データとセッション録音の突き合わせは、ディレクトリの隣接ではなくmeta.jsonの時刻対応(wall clock ↔ host time)経由になる。
- 制約・再評価条件:
  - 本ADRは開発診断が対象。診断を恒久機能(利用者向けトラブルシュート等)にする場合は成立しなくなり、新ADRで置換する。
