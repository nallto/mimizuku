# ADR-0017: 捕捉の欠落区間は、AECの外側で実測長の無音を挿入して時間軸を保つ

- ステータス: Accepted
- 日付: 2026-08-20
- 関連: #116, #93, ADR-0006(決定5: 時刻原点), ADR-0016(決定8で本件をスコープ外化), `docs/domain-pitfalls.md` #11 / #14 / #15 / #16 / #17

## Context(背景)

捕捉ソースの再構築中(録音中のデバイス切替、`docs/domain-pitfalls.md` #14 / #16 / #17)はバッファが1つも届かず、その時間が録音と文字起こしから消える。録音ファイルは壁時計より短くなり、再構築のたびに欠落が累積する。マイクとシステム音声で欠落量が異なるため、両トラックの相対的なずれ(=「自分」と「相手」の発言時刻のずれ)も広がる。実測では切替1回あたりマイク約1.9秒(マイク単体モード)、両方モードでマイク0.76秒・システム0.39秒が失われた(#116)。システム音声tapには再構築に加え、無音時にコールバック自体が来ない区間(#15)という同じ構造の欠落がある。

欠落長はデバイス・切替の種類・HALの状態で大きく変わり(実測0.4秒〜129秒)、上限も見えない。したがって**固定値で埋める設計は成立しない** ―― 実際の欠落長を毎回測って、その長さの無音を挿入する必要がある(#116の前提)。

検討した代替案:

- **ソース内部(yield地点)で無音を挿入する(却下)**: 挿入点は2箇所(`MicrophoneSession` / `TapSession`)で済むが、マイクの埋め無音がAECの状態機械を通ってしまう。`AecTimeline`のrebase(#93で実機検証済みの回復挙動)を打ち消し、`AecFeedScheduler`の保持上限(4秒)を超える欠落では埋めた無音自体が`HeldOverflowDrop`で捨てられる。実測129秒級の欠落を扱えない。
- **録音ファイル書き込み時(`AudioFileWriter`)で埋める(却下)**: writerはタイムスタンプを受け取っていない(`AudioSource.buffers()`契約は`AVAudioPCMBuffer`のみ)。契約を変えて全経路へタイムスタンプを運ぶ改修になり、文字起こし経路の欠落は別途埋める必要も残る。
- **AECの外側・`AudioRouter`直前で挿入する(採用)**: hostTimeがまだ残っている最後の地点(AEC出力の`AecFrame.hostTime` / tee・変換アダプタの`TimestampedAudioBuffer.hostTime`)で連続性を判定し、欠落分の無音をyieldしてからタイムスタンプを剥がす。AECの状態機械には一切介入せず(ADR-0016 決定8「時間軸はAECの収束と別に扱う」と整合)、録音と文字起こしの両方が同じ充填済みストリームを受け取る。

## Decision(決定)

1. 欠落判定はCoreの純ロジック`CaptureGapFiller`が行う。`AecTimeline`と同型の予測タイムライン(先頭時刻+積算フレーム数/レート)を正典とし、実測hostTimeが予測より**閾値超**遅れたら本物の欠落とみなし、差分をフレーム数へ換算して返す。時刻はすべて引数で受け取り、内部で時計を読まない(ADR-0016 決定2と同じ分割方針)。
2. 閾値は0.25秒とし、`AecTimeline`のcapture側rebase閾値と同値に揃える。**これは検知の閾値であり、埋める長さの定数ではない**(埋める長さは毎回の実測差分)。AEC出力経路の欠落はcaptureタイムラインのrebaseとして現れるため、これより小さい欠落はそもそも下流から観測できない。閾値以下のずれはジッタとして予測タイムラインに吸収させる。
3. 挿入点は4経路: (a) AEC出力のバッファ化(`makeProcessedStream` ―― 両方/マイク単体モードのマイク)、(b) `referenceTee`の下流(両方モードのシステム音声。AECの参照取り込みには実バッファのみを渡し、埋め無音は渡さない)、(c) `SystemAudioTapSource.buffers()`(システム音声のみモード)、(d) `MicrophoneSource.buffers()`(診断バイパス)。隠し参照tap(録音・文字起こしに出ない)には挿入しない。
4. 挿入する無音は**厳密ゼロ**で生成する(`SilenceBuffer`、確保後に明示ゼロ埋め)。`SpeechEngine`は厳密ゼロのバッファを解析へ供給せずタイムラインだけを進める(幻聴対策、pitfalls #11)ため、埋めた無音は文字起こしへ悪影響を与えずに`TranscriptSegment.start/end`を実時刻へ揃える。この性質はゼロ埋めに依存するため、無音生成をノイズフロア等で代替しない。
5. 長い欠落は1秒単位のチャンクで生成し、巨大な単一バッファの確保を避ける。無音の確保失敗はthrowする(録音経路はドロップ禁止 ―― 無言で時間を失わない)。
6. 実測が予測より**早い**方向の閾値超(通常は起きない)は、無音を挿入せず実測へ追従だけする。時間を削る操作はしない。
7. 埋めた欠落は`capture gap filled`としてログへ残す(ストリーム種別・実測秒数・フレーム数)。実機検証と将来の欠落分布の実測(#92)の観測手段。
8. 停止操作が再構築ブロック中に行われた場合の**末尾ギャップ**(最後のバッファ〜停止時刻)は本ADRのスコープ外とする。ストリーム終了後には挿入する機会がなく、停止時刻の配管という別機構が要るため、別Issue(#118)で扱う。通常停止では影響しない。

## Consequences(結果)

- 得るもの:
  - 再構築を含むセッションで録音ファイルの長さが壁時計と一致し(AAC変換の誤差を除く)、両トラックの相対ずれが再構築回数に比例して広がらなくなる。S7(再生)の音声・波形・文字起こしハイライトの同期前提が成立する。
  - システム音声tapの「無音時にコールバックが来ない」区間(#15)も同じ機構で正しく埋まる ―― 内容としても実際に無音だった時間であり、意味が一致する。
  - 判定ロジックはCoreの純ロジックとしてCIで検証できる(可変長の欠落・ジッタ非発火・丸め非累積をテストで固定)。
- 失うもの:
  - 0.25秒以下の欠落は検知できず、埋まらない(AAC変換のプライミング誤差85msと同水準の許容)。
  - 欠落が無音として録音に残るため、ファイルサイズは壁時計ぶんになる(欠落して短くなるより正しい振る舞いだが、分単位のブロックでは無音が長く入る)。
  - 末尾ギャップ(決定8)は残る。利用者が再構築ブロック中に停止した場合、その区間は依然として欠落する。
- 成立しなくなる条件: `AecTimeline`のcapture側rebase閾値(0.25秒)を変更する場合、決定2の同値前提が崩れるため本ADRの閾値も同時に見直す。
