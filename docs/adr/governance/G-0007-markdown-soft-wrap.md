# G-0007: Markdownはソフトラップを前提に整形する

- ステータス: Accepted
- 日付: 2026-07-28
- 関連: #80、G-0006

## Context(背景)

本プロジェクトではMarkdownの通常段落を幅で手動改行せず、エディタのソフトラップで表示する慣習があった。しかし規約にもformatterにも記録されていなかったため、人間やAgentがその慣習を発見できず、一般的な固定幅のハードラップが文書へ混入した。特にAgent共通ワークフローを整備した変更では多数の文書を同時に編集したため、影響が広がった。

手作業だけで統一する案は、暗黙知を残し再発を検出できないため採用しない。独自scriptで段落を結合する案は、Markdownの構文境界を誤って壊す危険があるため採用しない。Markdownの構文木を扱える既存formatterを固定バージョンで使い、CIと編集経路から同じ結果を得る必要がある。

## Decision(決定)

プロジェクト所有のMarkdownはPrettierを正確なバージョンでmiseに固定し、`proseWrap: never`で整形する。通常の文章は1段落を1物理行とし、表示幅による折り返しはエディタのソフトラップに任せる。段落、リスト、表、コードブロック、意図的なMarkdown hard breakなど意味を持つ改行は保持する。

`just fmt`を自動修正、`just check`内の`fmt-check`を未整形文書の検出経路とする。Claude Codeは既存のPostToolUseから単一ファイルを整形し、Codexと未知のAgentは共通の`AGENTS.md`と最終的な`just check`を保証経路とする。

release-pleaseが生成する`CHANGELOG.md`、外部由来の`third_party/`、gitignoreされた個人ローカル文書は対象外とする。これらの所有者や生成元とは独立して形式を変更しない。

## Consequences(結果)

文章の意味と表示幅が分離され、異なるエディタ幅でも不要な差分が生じにくくなる。人間と各Agentが暗黙の慣習を知らなくても、同じformatterとCIで形式を維持できる。

一方で、長い段落はソース上で長い1行になるため、閲覧環境ではソフトラップを有効にする必要がある。Prettierは表など通常段落以外のMarkdown構文も正規化するため、バージョン更新時は差分と構文保持を確認する。順序とは独立した安定IDを持つ項目は、formatterによる連番化を避けるため、順序付きリストの番号ではなく本文中の`#N`として表現する。対象範囲やformatterを変える場合は、この判断を置き換える新しいgovernance ADRを作成する。
