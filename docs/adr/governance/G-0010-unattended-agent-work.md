# G-0010: 無人実行の許可範囲と報告キュー

- ステータス: Accepted
- 日付: 2026-08-17
- 関連: #105, G-0001, G-0006, G-0008, G-0009

## Context(背景)

このリポジトリの作業規律は、外向き・不可逆な操作の直前に利用者の明示承認を求めている。承認者が不在の時間帯は、承認を必要としない作業まで止まる。実機・TCCを要する検証は人しか実行できない(`docs/domain-pitfalls.md` #8)が、その手前の実装、機械検証、docs更新、調査は人の介在なしに到達できる。停止点を「人しかできないこと」に限定できれば、待ち時間を作業時間へ変えられる。

同時に2つの運用上の問題がある。1つは、多エージェントのオーケストレーション(Workflow)が起動ごとに明示的なopt-inを必要とするため、恒久的な作業手順として使えないこと。もう1つは、並列実行した調査の結果を一度にまとめて報告すると、利用者が読み切れず判断も滞ることである。

検討した代替案:

- **現状維持(却下)**: 承認者不在の間、承認を要しない作業まで停止する。実機検証待ちのIssueが、実機以外の理由でも進まない。
- **無人実行にすべての操作を許可する(却下)**: mergeとブランチ削除、外部公開は不可逆であり、利用者が毎回diffをレビューする前提(AGENTS.md)を壊す。
- **実機依存の作業を避けて進める(却下)**: 録音と捕捉が製品の中核であり、実機依存を避けると本質的な作業がほぼすべて対象外になる。
- **到達可能な限界まで進め、停止点をラベルとキューで表す(採用)**: 人しかできない地点で止め、その地点を機械可読な状態として残せる。
- **報告待ちをIssueコメントで表現する(却下)**: 未報告か報告済みかという個人の作業状態をチームの記録へ混ぜることになり、優先順位も表現できない。
- **報告待ちを会話コンテキストやAIのauto memoryに持つ(却下)**: セッションで失われ、リポジトリからも発見できない。AGENTS.md「知識の置き場所」に反する。

## Decision(決定)

1. skill経由のWorkflow起動を恒久的に許可する。Workflowを使うskillは、目的、停止条件、1回の起動で使うエージェント数の上限をSKILL.mdに明記する。
2. 手順本文は共通skill(`.agents/skills/`)に置き、Workflowスクリプトは製品別アダプター側に置く。Workflowを持たないAgentは同じ本文を逐次実行して同一の出力形式を満たす。
3. 一定間隔の定期巡回を実施する。間隔と稼働時間帯はリポジトリに固定せず、夜間にも限定しない。製品別のローカル登録手順は`patrol` skillを追加する変更(#109)で`docs/development.md`へ置く。
4. 無人実行で許可する外向き操作は、作業ブランチへのpushと、draft PRの作成・更新に限る。
5. 無人実行で禁止する操作は、`main`への直接push、あらゆるmerge、ブランチ削除、force push、リポジトリ設定の変更、リリース・配布・告知・リポジトリ外サービスへの送信、秘密情報の読み書き、実機・TCCを要する検証の完了判定とする。作業ブランチと自リポジトリのdraft PRはこの「公開」に含めない。
6. 無人実行が着手できるのは、承認済み計画の続行と、承認を要さない作業(調査、docsの草案、既存計画に含まれる実装と機械検証)に限る。新たに非自明な変更の着手判断が必要になったら、着手せずに計画案をキューへ積んで停止する。これはG-0008の計画承認を緩和するものではなく、承認待ちの位置を変えない。
7. 無人実行ではコミット前の変更確認を受けられないため、コミットとpushは行い、変更確認はdraft PRのdiffに対して事後に受ける。この1点についてはG-0008の「コミット前の変更確認」を無人経路に限って緩和する。統合(merge)前の承認は緩和しない。
8. 無人実行が作るPRはdraftとし、`needs-human`ラベルを付ける。
9. `needs-human`は「人の介在なしに進められない状態」を表す唯一のラベルとする。種類(実機・TCC検証 / 設計・UXの判断 / 認証情報・アカウント操作 / 不可逆操作の承認)と具体手順は、Issue・PR本文の「人の介在が必要な項目」節に書く。既存の`decision`はタスク種別を表すラベルであり、意味を重ねない。Issue側のフォームテンプレートは人の報告用であり、この節のフィールドを追加しない。
10. 報告待ちの通知は`local/agent-artifacts/report-queue/`へ1件1ファイルで置く。パスはメインチェックアウトのルート(`git rev-parse --path-format=absolute --git-common-dir`の親)基準で解決し、worktree内の同名パスへ積まない。worktreeは撤収で消えるため、そこへ積むとキューが失われる。
11. 報告は優先度規則に従い、1ターンにつき1件、最優先のものから順に行う。優先度規則と報告手順の正典は`.agents/skills/report-queue/SKILL.md`とし、他のファイルへ複製しない。
12. 無人実行は`local/worktrees/`のworktreeで行い、利用者が使うmain checkoutを占有しない(G-0009)。

## Consequences(結果)

- 得るもの:
  - 承認者が不在の時間帯も、承認を要しない作業を進められる。休日や日中の中断中も同じ扱いになる。
  - 実機検証待ちが「停止」ではなく「キューに積まれた1項目」になり、実機を触れる時間にまとめて消化できる。
  - 報告が1件ずつになり、優先度の高い判断から順に処理できる。
  - Workflowを毎回の確認なしに、定義済みの手順として使える。
- 失うもの:
  - 利用者がレビューする前の変更がリモートのdraft PRとして現れる。レビュー対象がローカルdiffだけではなくなる。本リポジトリは公開されているため、未レビューの作業ブランチも公開状態になる。
  - 秘密情報を止める機械的防御(CIのgitleaks)はpushの後に動く。push前の防御は規律とhookに依存する。
  - Workflowの常設化によりトークン消費が増える。歯止めは各SKILL.mdのエージェント数上限に依存する。
  - 報告キューはgit管理外(`/local/*`はgitignore)であり、端末間では共有されない。
- 維持する保証:
  - merge、ブランチ削除、PR統合の承認手順はG-0001とG-0008から変更しない。無人実行はこれらを行わない。緩和するのは決定7の「コミット前の変更確認」1点のみで、無人経路に限る。
  - ハード制約(private API不使用、音声・文字起こしのデバイス外送信禁止)は無人実行でも変わらない。
  - 実機・TCC依存の検証結果を人以外が「検証済み」と記録することはない(`docs/domain-pitfalls.md` #8)。
